# Using GaPSE from Jupyter notebooks

GaPSE is currently **unregistered**, so notebooks should use a separate Julia environment and refer to GaPSE through its local path.

This directory already carries the right `Project.toml`, so **as a user you only need**

```julia
julia> using Pkg

julia> Pkg.activate(".")        # from inside this directory

julia> Pkg.instantiate()        # downloads and installs everything, GaPSE included
```

`Project.toml` is tracked by git, `Manifest.toml` is not: it is rebuilt by `instantiate` on each machine.

Below we explain how that `Project.toml` was made, in case you need to recreate it.
The same approach applies to the notebooks inside `../theory` or to any personal directory of yours.

> [!IMPORTANT]
> You don't have to run the following commands, because we provide already a correct `Project.toml` file.
> We just show how we did it, for your information.

<br>
<br>



## TL;DR


```bash
mkdir -p ipynbs && cd ipynbs
PATH_TO_GAPSE=".."              # set this variable to the directory of GaPSE
rm -f Project.toml Manifest.toml
julia --project=. -e "using Pkg; Pkg.develop(path=\"$PATH_TO_GAPSE\")"
cat << EOF >> Project.toml

[sources]
GaPSE = {path = "$PATH_TO_GAPSE"}
EOF
julia --project=. -e 'using Pkg; Pkg.add(["Plots", "PythonPlot", "LaTeXStrings", "DelimitedFiles", "Printf", "Dierckx", "GridInterpolations"])'
julia --project=. -e 'using Pkg; Pkg.instantiate(); Pkg.precompile()'
```

The first `Pkg.develop` is what writes the `GaPSE` entry (with its UUID) into `[deps]`; the `[sources]`
table is what makes that entry portable, since it is the only place where the path is written down and
tracked by git.

<br>



## 1. Re-creating the `ipynbs` notebook environment

We will assume the following dir structure

```text
GaPSE/
├── Project.toml
├── src/
│   └── GaPSE.jl
└── ipynbs/
    └── ...
```

and we will re-create the `Project.toml` needed for this directory.


```bash
$ cd ~/my-path/GaPSE
$ mkdir -p ./ipynbs
$ cd ./ipynbs
$ rm -f Project.toml            # we recreate it from scratch
$ julia

julia>                          # enter Pkg mode by typing "]"  => prompt will change
(@v1.12) pkg> activate .        # activate the current dir project  => prompt will change again
(ipynbs) pkg> develop ..        # where ".." is the directory where GaPSE is, i.e. the parent dir of "ipynbs"
  ...
  ...
(ipynbs) pkg>                   # go back to command mode by typing "Backspace"
julia>                          # exit from julia with "^D"

# Add manually the "sources" entry for GaPSE in the "Project.toml", with the correct path (here "..")
$ cat << EOF >> Project.toml

[sources]
GaPSE = {path = ".."}
EOF
$ julia

# Then, in the Julia REPL again:
julia>                          # enter Pkg mode by typing "]"  => prompt will change
(@v1.12) pkg> activate .        # activate the current dir project  => prompt will change again
(ipynbs) pkg> add Plots, PythonPlot, LaTeXStrings, DelimitedFiles, Printf
(ipynbs) pkg> add Dierckx, GridInterpolations
(ipynbs) pkg> precompile        # compile the source code of these packages into efficient cached artifacts (.ji files)
```

This creates `ipynbs/Project.toml` and `ipynbs/Manifest.toml`.

(`add` already resolves the dependency graph, writes `Manifest.toml` and installs everything, so
`instantiate` right after it has nothing left to do; it is the command *another* user needs, who starts
from the `Project.toml` committed here.)

The resulting `Project.toml` will have the essential structure:

```toml
[deps]
GaPSE = "d1bf0294-456c-4ffb-813c-36d532d2da2e"
Plots = "..."
LaTeXStrings = "..."

[sources]
GaPSE = {path = ".."}
```

NOTE: the exact UUIDs and additional entries should be generated by `Pkg`, rather than written manually.

## 2. Why at all we need to do that?

### 2.1 Julia Notebook Environment

> [!IMPORTANT]
> The active environment of the kernel has to be the directory of the notebook itself.

This does **not** happen by itself: it depends on how the Julia kernel was started.

- **VS Code** (Julia + Jupyter extensions) starts the kernel in the environment shown in its
  status bar, which by default is the nearest `Project.toml`: it works out of the box;
- a kernel installed with `IJulia.installkernel("Julia", "--project=@.")`, or a Jupyter started with
  `JULIA_PROJECT=@.` exported, activates the nearest `Project.toml` at or above the working
  directory: it works too;
- a **stock** `IJulia.installkernel("Julia")` passes no `--project` at all, so the kernel starts in
  the shared `@v1.12` environment and `using GaPSE` fails there.

That is why the first cell of every notebook in this directory is

```julia
using Pkg
Pkg.activate(@__DIR__)
```

In a notebook `@__DIR__` falls back to `pwd()`, which is the directory of the notebook, so those two
lines are a no-op in the first two cases and the fix in the third one. Delete them if your kernel is
always set up the right way.

=> There are **two different Julia environments** that come into play:

```text
GaPSE/Project.toml   ->  dependencies of the GaPSE package  ->  TwoFAST, FFTW, HCubature, ...

ipynbs/Project.toml  ->  dependencies of the notebook       ->  GaPSE, Plots, LaTeXStrings, ...
```

=> The notebook does **not** need to list GaPSE's dependencies again!

For example, if the notebook contains a cell with:

```julia
using GaPSE
using Plots
using LaTeXStrings
```

then:

* `GaPSE`, `Plots`, and `LaTeXStrings` are direct dependencies of the **notebook environment**;
* `TwoFAST`, `FFTW`, `HCubature`, etc. remain dependencies of **GaPSE**.

Julia resolves the dependency graph recursively, so GaPSE can load its own dependencies from its own `Project.toml`.

**A package should be added to the environment that directly uses it.**

This also means that a package reached *through* GaPSE needs no entry here: `GaPSE.TwoFAST.xicalc(...)`
works with `using GaPSE` alone, and only a bare `xicalc(...)` would require `TwoFAST` in this
`Project.toml`.



### 2.2 Why `include` is not the right solution?

Do **not** use `include("../src/GaPSE.jl")` to use GaPSE as a package!

In Julia, `include` only evaluates the source file, i.e. it's like you are copy-pasting the whole code in that cell.
It does not make Julia treat GaPSE as a package dependency with its own dependency environment.

Concretely, the `using TwoFAST` inside the GaPSE sources is then resolved against the *notebook's*
environment, and the include dies with

```text
LoadError: ArgumentError: Package TwoFAST [0dd23c3e-f403-11e8-3e11-4dddf690af97] is required
but does not seem to be installed
```

Instead, use `using GaPSE` with GaPSE declared in the notebook environment:

```toml
[deps]
GaPSE = "d1bf0294-456c-4ffb-813c-36d532d2da2e"

[sources]
GaPSE = {path = ".."}
```

The `[sources]` entry tells Pkg where the unregistered package GaPSE is located.
This is the mechanism provided by modern Pkg for local/unregistered dependencies.

NOTE: `[sources]` section has to be created and edited manually: `Pkg.develop(path=...)` only writes
the `[deps]` entry, and records the path in `Manifest.toml` - which is gitignored, so without
`[sources]` a fresh clone would not know where GaPSE is.

## 3. The packages of this environment

| package | why |
|---|---|
| `GaPSE` | the package itself, through its `[sources]` path |
| `Plots` | every figure |
| `PythonPlot` | the matplotlib backend of `Plots`, selected with `pythonplot()` |
| `LaTeXStrings` | the `L"..."` labels |
| `Printf` | `@printf` / `@sprintf` |
| `DelimitedFiles` | `readdlm`, to read the `.txt` outputs back |
| `Dierckx` | `Spline1D`, used to interpolate the results *after* GaPSE computed them |
| `GridInterpolations` | `RectangleGrid` + `interpolate`, for the 2D window-function maps |

Which notebook needs what:

| notebook | `using` |
|---|---|
| `TUTORIAL.ipynb` | `Plots`, `LaTeXStrings`, `Printf` |
| `Generic_Window.ipynb` | `Plots`, `LaTeXStrings`, `Printf`, `Dierckx` |
| `eBOSS_Window.ipynb` | `Plots`, `LaTeXStrings` |
| `PS_L01234.ipynb` | `Plots`, `LaTeXStrings`, `Printf`, `DelimitedFiles`, `Dierckx`, `GridInterpolations` |
| `Computations_b1p5-sb0-fevo0.ipynb` | the same as `PS_L01234.ipynb` |

`ProgressMeter`, `QuadGK`, `Trapz`, `LegendrePolynomials`, `SpecialFunctions` and `TwoFAST` used to be

and the `Project.toml`. Add them back here if you start calling them directly.
